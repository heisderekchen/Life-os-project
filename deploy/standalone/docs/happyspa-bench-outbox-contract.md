# HappyspaBench read-only outbox contract v2026-10-20.v1

This contract is for the NEO controller's **local producer only**. It does not
authorize promotion changes, browser automation, credential creation, or
upstream writes. Every amount is an integer number of fen. Every timestamp is
an RFC3339 instant with `+08:00` offset (`Asia/Shanghai`).

## Identity and delivery

- `producer`: fixed string `neo-happyspa-readonly`.
- `taskId`: `499537ec-0aec-4a2e-8b1a-5526c9864d66`.
- `contractVersion`: `2026-10-20.v1`.
- `eventId`: stable UUID/ULID generated by NEO; retries must reuse it.
- `observedAt`: time the source was observed, not the delivery time.
- `acceptedAt`: assigned by the private-workbench receiver.
- Transport target after receiver deployment: `POST
  /workbench/api/happyspa-bench/outbox` with `Authorization: Bearer <approved
  outbox token>`. The token is accepted only through the trusted HTTPS proxy.

The repository contains the browser-session snapshot GET and a fail-closed,
bounded receiver. It is inactive until an approved secret source supplies
`HAPPYSPA_BENCH_OUTBOX_TOKEN`; an empty value rejects every machine request.
The machine identity is fixed to `neo-happyspa-readonly`, is limited to this
POST path, and cannot access any other private-workbench or advertising API.
NEO must not call POST until the reviewed change is deployed and that secret is
provisioned through the approved secret channel.

## Envelope

```json
{
  "contractVersion": "2026-10-20.v1",
  "producer": "neo-happyspa-readonly",
  "taskId": "499537ec-0aec-4a2e-8b1a-5526c9864d66",
  "eventId": "01J...",
  "kind": "official_snapshot",
  "observedAt": "2026-10-20T10:16:16+08:00",
  "payload": {}
}
```

Allowed `kind` values are exactly `official_snapshot`, `neo_heartbeat`, and
`plan_confirmation`.

## Event payloads

### `official_snapshot`

```json
{
  "planId": "极速推广20260512557",
  "planType": "极速推",
  "todaySpendFen": null,
  "sourceAsOf": null,
  "officialPlanCount": 9,
  "targetStatus": "running",
  "evidence": [{"kind":"collector_file","reference":"relative-redacted-path"}]
}
```

`todaySpendFen` and `sourceAsOf` may be null; null is never converted to zero.
Evidence references are relative, redacted identifiers only, never cookies,
browser profiles, account IDs, credentials, or full URLs.

## Receiver and storage rules

- Migration `0101_happyspa_bench_outbox.sql` creates `happyspa_bench_outbox`.
- Receiver validates envelope version, producer allowlist, task ID, event kind,
  ISO time, non-negative integer fen, and payload shape before acceptance.
- It writes using the adapter's guarded upsert. A retry reuses `eventId`; an
  observation older than the stored observation is a no-op.
- Snapshot selects the latest accepted event per kind. Freshness is 10 minutes:
  no event is `pending_confirmation`, malformed time is `failed`, an older
  event is `stale`, otherwise `fresh`.

## Required coordination before live delivery

1. The NEO maintainer provides an existing private-workbench service principal
   or approved request-signing identity, scoped only to this task and POST path.
2. The workbench maintainer deploys a receiver which verifies that identity and
   maps it to producer `neo-happyspa-readonly`; this repository currently has
   no such service-principal verifier.
3. Both maintainers agree a durable local outbox location and retention policy.
4. The receiver accepts `plan_confirmation` only when its source, schema,
   business date, task scope, and caller permission validate. No record is
   inferred from shared logs or from the UI reference image.
