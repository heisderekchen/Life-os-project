# 搜索执行记录

从 1.0.13 起，新建及重试搜索都会生成独立的 `runId`。记录持续写入数据目录，重试保留以前的执行；旧执行只有渠道汇总，无法补回当时未保存的候选和响应。

## 入口与存储

- 任务详情页 → **搜索调试记录** → 选择一轮 → **下载本轮调试记录**。
- `GET /fashion/api/tasks/<taskId>/debug?run=<runId>` 下载 JSONL；不传 run 时下载最新轮。执行中也可下载已写入的部分。
- 使用现有工作台会话；只允许下载当前账号自己的任务。文件不位于静态资源目录。
- 路径：`<fashion dataDir>/search-debug/<sha256(account)>/<taskId>/<runId>.jsonl`，目录 0700、文件 0600。随现有 Fashion 数据目录备份。重试和版本发布不删除记录，目前不自动按时间清理。
- 任务 API 的 `debugRuns` 只包含执行编号、版本、开始/结束、状态、耗时、结果数、事件/字节数、采样限制及写入错误，不把大日志塞入轮询响应。

## 排查顺序

每行包含 `schemaVersion`、`taskId`、`runId`、递增 `seq`、`at`、`elapsedMs`、`type`、`data`。并发事件按实际发生时间排列；通过 `entryId`、`channelId`、`candidateId`、HTTP `requestId` 和 URL 关联。队列事件另带站点范围。

1. `run.started` / `plan.created` / `plan.entry`：原始条件、代码版本、来源范围、排除域名、规划入口、资源预算、是否续跑、上一轮编号。
2. `deepseek.request` / `deepseek.response` / `planning.*`：实际模型、规划提示和输入、原始响应（含检索结果/分数/摘要）、解析后的英文意图和检索式、规划失败与词表回退。
3. `search.query`：实际发出的完整查询、站点限制是否因 128 字符预算未写入查询（范围仍在本地过滤）；`deepseek.attempt*` 保留每次尝试、错误、耗时及是否重试。
4. `http.request` / `http.response` / `http.error`：请求方法与网址、HTTP 状态、重定向、MIME、声明长度、响应头到达耗时、上游请求编号、网络错误及 cause code。不会保存 Cookie、鉴权头或密钥。
5. `candidate.prefilter`：原始候选标题、URL、图片、日期、分数/摘要、对照意图、来源范围、保留/淘汰及首个失败规则。被初筛淘汰的候选也保留。
6. `document.*` / `source.*`：读取的原页/Feed、最终 URL、文档读取总耗时、内容 SHA-256、标题、裁剪后的公开页面样本、解析出的候选和商品证据。来源阅读器在相关性过滤中记录分类计数和前 10 个例子；每源最多 6 候选的预算也记录。可识别空内容、反爬页面、跳转、解析无商品与标题不符。
7. `candidate.page.evidence` / `candidate.image.*` / `image.*`：商品与当前页面归属关系、选中的标题和图片、来源声明、日期、图片格式/大小/尺寸/哈希、异常、通过或淘汰的具体规则。缺少当前商品证据时另记录未做相关性筛选的结构化商品，便于定位解析与匹配的分界。
8. `candidate.skipped`：重复候选、重复图片哈希、续跑已完成、候选预算、结果预算。跳过与淘汰分开记录。
9. `queue.entry.*`：队列内每组来源的状态变化、失败、局部结果、各渠道原因及检查点摘要。不会被任务页的“公开来源索引”汇总覆盖。
10. `run.failed` / `run.finished`：异常、超时原因、最终渠道汇总、保留结果和总耗时。进程重启后读取任务会追加 `run.interrupted`；不伪装成正常结束。崩溃导致半行时，导出加入 `trace.recovery` 说明，原文件保留。

## 容量与完整性

- 每轮普通事件上限 16 MiB / 30,000 条；保留结束事件空间。超限省略数量在任务和导出快照中明确给出。
- 网页样本单份最多 64,000 字符、每轮样本总预算 4 MiB；可执行脚本和表单值会移除。样本并非完整 HTML，保留原文长度与哈希，以及裁剪/省略标记。商品提取证据单独记录。
- 字符串最多 65,536 字符、数组最多 1,000 项、嵌套最多 14 层，超限有标记。来源阅读器的过滤例子是采样，计数不受例子数量限制。
- 事件按 100 ms 或 64 KiB 分批追加，结束及下载前等待写入队列。崩溃可能丢失尚未刷新的最后一批；服务重启标为中断。系统不承诺断电时最后一批已 fsync。
- 日志写入失败单独显示 `storageError`，不会把它解释成“没有搜索结果”。下载末行 `export.snapshot` 给出当时执行状态、采样及存储错误；不属于执行事件序列。
- HTTP 耗时测到响应头；`document.read` / `image.read` 的耗时包含响应体读取。不同层耗时不可直接相加。
- 日志用于解释现有搜索行为，不代表图片已经通过视觉质量判断；结果仍需人工核查。

## 1.0.14 核对规则修正

- 查询规划显式关闭 thinking；空正文或输出截断单独记录，词表覆盖冬季/休闲组合。
- `ProductGroup` 与 `Product` 都可提供当前商品证据；相关性同时核对商品名称、类别、描述及性别字段，不读取全站导航作为商品证据。
- 记录正向季节/用途表达：snow、insulated、thermal、cold weather 等支持冬季，sneaker、everyday、lifestyle 等支持休闲；品牌、材质、颜色等其他要求继续核对。
- Shopify 的 collection/product 与 canonical product 路径按同一商品归属核对，页面里的关联推荐商品不能挤掉当前商品；多个不同的当前商品仍拒绝自动选图。
- 原页已有商品而相关性不符，记录 `sourceIntentMismatch`；未提取到商品图才记录 `productEvidenceMissing`，多商品歧义记录 `ambiguousProductPage`。交付前重新核验使用相同规则。
- 零结果文案区分初筛数量、实际核对数量和原因；原页访问失败仍保留 HTTP 状态/网络 cause，不推断为条件太窄。

## 1.0.15 广泛检索

- 普通广泛搜索目标为 100 张真实下载、尺寸合格、归属明确、相关且去重的图片，候选预算提高到 1,200；不把搜索命中数当作已取得图片数。
- `broad.started/intent/round.completed/round.failed/finished` 保存英文需求、目标、轮次、增量、耗时及是否达标；不足 100 时明确显示缺口，不造数据。
- `catalogue.listing/filtered/failed/backoff/cache.hit` 保存公开品牌/零售商品目录的地址、页数、文档哈希、过滤分类与例子，以及命中商品自己的属性。目录缓存最长 15 分钟/32 MiB，仅用于发现；每张图片重新读取对应商品的公开 `.js` 数据，核对 handle、来源域名、原图声明和属性。结果保存 `evidenceURL`，交付前重新读取同一证据。
- Gioseppo、Rieker、Steve Madden、Allbirds、Dolce Vita、Larroude、The Sports Edit 使用公开店面 JSON；允许的类型和排除域名继续生效。目录并非全部有效采集器，访问失败逐项保留。
- 公开 JSON 使用受限 curl 兼容传输；只对已列出的公开来源、规定路径、HTTPS GET 生效。无 shell、无自动跳转、无鉴权/会话，禁用 curl 配置文件且不传环境密钥；最大 8 MiB/15 秒。执行环境需有 curl（现有部署健康检查也使用 curl）。普通网页和图片仍沿用现有 DNS/私网/重定向校验。请求日志标明 `curl-public-json`。
- 分页补充后仍不足时，按原英文需求执行不同站点/措辞搜索，最多 14 个检索式；来源或视图失败后继续补充。每来源 1.6 秒请求间隔，429 遵守有限退避；总任务上限 12 分钟，已完成图片实时保存。
- 每商品最多两个不同视角；检查前八张声明图片，重复或失败会继续找下一视角。SHA-256 精确去重，像素解码后使用色彩及 64 位差分指纹过滤近似图；同商品使用更严格的相似视角判定。`candidate.skipped: nearDuplicateImage` 保留跳过原因。
- 相关性改成完整词匹配；促销/活动/关联款标签不参与属性证据，`winterpromo` 不代表冬季鞋款。冬季休闲排除露趾/细高跟等冲突类型。颜色使用当前商品的主色，白鞋底或关联白色款不能使黑鞋成为小白鞋。`loafers-flats` 等导航合并标签不作为鞋型证据；自身名称、分类及 Type/Style 字段出现冲突时拒绝串类。泛化的 WOMAN 分类可由明确鞋款名称/独立鞋型标签补足，儿童年龄分类不能仅凭 female 混入成人女鞋。
- 全部结果仍为待人工核查，不自动标记已核查、选入或交付。自动质量检查与人工视觉判断分开。

### 可复用真实网络回归

```sh
node --test deploy/standalone/fashion/test/*.test.mjs
FASHION_ROUND=local-01 node deploy/standalone/fashion/scripts/broad-benchmark.mjs
FASHION_ROUND=production-01 FASHION_BENCHMARK_BASE=https://happyspa.studio/fashion node deploy/standalone/fashion/scripts/broad-benchmark.mjs
```

默认覆盖女款冬季休闲鞋、小白鞋、乐福鞋、芭蕾平底鞋、凉鞋、短靴（不限时间，三类来源）。`FASHION_SUBJECTS` 可传主题 JSON 数组，`FASHION_BENCHMARK_OUT` 可指定证据目录。保存任务、逐图原图哈希/实际尺寸/近似重复检查、完整 JSONL、100 图总览及汇总；`automaticPass` 与 `visualReview` 分开，数量达标不代表视觉验收完成。生产回归使用自己的独立访客会话，不访问其他用户任务，也不修改人工核查状态。

## 1.0.16 原需求约束锁定

- `planning.constraints.locked` 记录模型意图与实际执行意图。词表已完整翻成英文或原需求本身为英文时，直接锁定它作为商品筛选约束；模型只扩展检索式，不能把“小白鞋/white sneakers”放宽成“white shoes”，也不能丢掉 ankle、winter、颜色、材质等原有条件。未知中文仍要求完整英文翻译，规划失败不会发送中英混杂搜索词。
- 规划失败时同时重置检索式和筛选意图，防止部分解析后的弱条件残留。
- 真实像素检查拒绝近乎全黑或全白的图片，记录 `imageQualityRejected` 与 `IMAGE_QUALITY`，失败视图继续补充其他商品原图。

## 1.0.17 使用品牌公开目录中的逐商品原始证据

生产回归中，1.0.16 的冬季组达到 100，但小白鞋仅 64。其日志有 92 个原网页/逐商品数据读取失败，HTTP 429 32 次、403 27 次。反复访问单品接口并未增加来源证据；相同品牌已经成功返回完整公开商品目录。

- 商品目录原文作为一种明确的第一方证据：按来源同域、唯一商品 ID、标准 handle/商品链接，选择该条记录自己的属性及图片数组。拒绝跨域、错误 ID/链接、重复 ID、非法查询参数及其他商品图片。不会把目录里任意图片当成当前商品图，也不声称已读取单品 HTML。
- 证据类型 `public-product-catalogue`、`evidenceURL`、实际来源获取时间 `evidenceFetchedAt` 和原始文档 SHA-256 均保留。目录快照在一次核对中复用，不再为每件商品请求 `.js`；每张图片依然真实下载、解码、尺寸/质量检查及精确/近似去重。
- 先尝试两页第一方目录，再核对公开网页候选；检索式扩展与原条件锁定继续独立执行。
- 目录缓存按原文字节三倍估算占用，维持 32 MiB 预算；单轮核对共享已取得的原文及已解析记录。HTTP 读取、缓存命中、每条商品绑定与淘汰过程分别记录。
- 交付前重新读取每份目录一次，重新按同一 ID/链接/属性/图片绑定；分页变动时用原商品 `.js` 再核验。原始来源页面、目录证据和图片哈希同时保留在导出文件中。
- 仍保留严格筛选及待人工核查状态；批量证据路径只减少重复网络请求。
