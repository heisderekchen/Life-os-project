# 动态任务紧凑列表：设计与 LUNA 实施任务

日期：2026-10-16。来源：用户本轮两张 myOS 动态任务截图及明确的优化、交给 LUNA 实施指令。范围：列表与筛选 UI；保留已有品牌、任务数据和详情流程。

## 页面目标

用户需要快速扫过尽可能多的任务及所属项目。优先级是信息密度、清晰的任务名和项目归属、直接筛选、可靠的现有操作。当前每条大卡片的标签区、材料块和操作页脚合并为一行；四个统计块变为紧凑筛选。

## 确定的布局

1. 第一行保留「我的任务 / 持续任务」页签、列表/看板切换及添加入口，避免任何页签均分占满页面的大框。工具栏紧凑排布，桌面搜索与现有操作同排，窄屏自然换行。
2. 第二行是统一的筛选栏：全部 N、进行中 N、待办 N、已逾期 N、已完成 N。用低矮的文字筛选按钮，当前项有明确的颜色和底线/轻背景，使用 aria-pressed；删除重复的「按状态筛选」入口和原统计卡。数量、结果和点击逻辑共享谓词；进行中/待办包含逾期项，逾期为独立交叉条件，已完成永不计入逾期。默认全部。结果旁显示「显示 X / 共 Y」，搜索与筛选叠加，空结果允许清空条件。
3. 桌面每条任务一行（目标 48–52px）：完成复选框 | 任务名（最大弹性宽度）| 所属项目 | 状态 | 优先级 | 截止日期 | 更多操作。列对齐、轻分隔线，不要逐条圆角卡片、材料框、操作页脚、彩色粗侧边或重复进场动画。标题一行截断，完整内容仍可点击或键盘打开详情。项目只使用真实关联；缺失显示「未关联项目」，不猜测。
4. 材料、完整描述、最新进展、标签、子任务与运行记录保留在现有详情内。列表更多菜单收纳开始/完成、编辑、删除，支持键盘与触屏；删除沿用已有确认路径，禁止直接绕过。完成复选框、更多菜单不触发行详情点击。
5. 手机每条任务最多两行，第一行为完成控件、任务名和更多；第二行精简展示项目/状态/优先级/日期。触控区域至少 44px，390/360px 无横向页面滚动，不能仅靠 hover 访问操作。桌面目标 1440×900 首屏至少 10 条、1920×1080 至少 14 条（用足量固定样例验证，不伪造生产数据）。

## 状态与动效

筛选和搜索立即反馈；仅必要的 hover/focus 颜色反馈 100–150ms；不为每行添加位移、缩放、弹跳或重复入场。尊重 reduced-motion。选中行、完成、加载、错误、无任务、无筛选结果均需明确可辨；原多选、批量操作、看板和持续任务语义保持。

## 实施与验收

LUNA 负责 tasks-page.tsx、必要的 interface-copy/i18n 文案，以及真正覆盖现有行为的少量组件测试。使用当前 React/Tailwind/Radix 组件，不添加视觉或动画依赖。注意其他分支上的 Dot 项目/类型关联 PR27 独立于此 UI 工作；不合并该分支、不改导入和后端。

交付前完成类型检查、相关 lint、现有任务详情集成测试及筛选边界验证。主代理复核实际浏览器桌面和手机，覆盖长中英标题/项目名、已完成、逾期、无日期、筛选叠加搜索、空结果、键盘进入详情、完成复选框、更多菜单、多选及 reduced-motion；保存前后截图和实际行高/首屏数量。只作一次批量修复和一次确认。提交结果为本地可审阅分支，不自动合并、发布或更改生产数据。
